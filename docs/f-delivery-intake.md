## 确认接口

`GET /api/delivery/:sourceProjectId/intake` 恢复既有确认及进度；`POST` 仅接受 `manifestUrl / manifestHash / rejectedIds`。沿用服务器全局身份认证，校验同源和 JSON；请求不能改账号、媒体链接或需求额度。

清单以生产项目的本地 `deliver-page/manifest.json` 为准，核对 CDN 地址、稳定条目ID、目标账号与测试范围。浏览器清单摘要和服务器一致后，冻结确认到确定性 `BI-<摘要>` 项目；并发点击、响应丢失、服务器重启复用同一项目。先以paused状态唯一保存冻结输入，再初始化磁盘文件，初始化事件与active状态原子写入；磁盘临时失败保持paused，恢复只写库内赢家输入，不覆盖或自动恢复用户明确暂停的已初始化任务。拒绝未知ID、篡改清单、全否决和跨批次输入。

项目沿用原生事件调度器；卡片执行环境先 preflight。未注册入池 workflow 或环境缺失则拒绝确认并说明，没有写池。已保存但调度暂失效的项目留在原生状态，下次正常调度恢复。

## Agent 与完成校验

Base定位以非敏感 `bufferTarget.baseId/tableId` 传递，不能命名为baseToken以免通用输入脱敏隐藏；不放宽全局脱敏规则。Agent 从确认输入、前序 brief、策划案生成逐条文案；只读核实合同与账号。`nightshiftctl intake-plan` 先对成片逐条 ffprobe，再按真实池记录计算写入计划。先占用既有排期，再安排更早待排期库存和本批新片；同账号同日不重复，不超5条额度。

本次试点从确认后的下一个当地日开始，取7个日历日内5个工作日，当地19:50，IANA时区换算UTC。该试点时段不覆盖客户的原始需求配置；明示到任务输入，可追溯。额外新片无日期待排期，不安排到后续周期。

按 `sourceProjectId:contentItemId` 幂等 upsert，仅更新计划指定的记录。副作用走原生外部操作台账。服务端完成校验再独立 ffprobe 和读取 Base：1080×1920、媒体可读、链接/账号/市场/语言/时区/日期/文案/数量逐项一致。本批≥5条但该周期没排足5个计划，不能通过。手写 recordedAll 不能代替真实回读。
